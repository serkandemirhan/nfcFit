2026-11-09. All 44 images in the latest Trainer package were inspected, including the 27 broad regression screenshots and 17 precision screenshots. Findings refer to actual rendered elements, not generic spacing requests.

Priority: Program Builder and Workout Builder desktop first, then the same spacing/action/state rules on mobile, libraries, reviews and progress. Preserve business logic, routes, API contracts, authorization and historical workout snapshots.

## Design decisions

Use a 1440px bounded Trainer workspace, 16–20px panels, 16px grid gaps, compact 12px field gaps, and 16px mobile gutters. Retain the dark navy surface, lime primary action and emerald brand. Use one page title, a breadcrumb, one publication indicator and one persistent save-state surface. Calendar is the program focus; exercise targets are the workout focus. Secondary settings and optional guidance start collapsed rather than introducing large empty columns. Mobile controls retain a 44px touch target.

Saving scope is explicit: a day application changes the local program draft; a reusable-template save persists only that template; program save/publication persists the program through the existing API. No client success state may precede a successful write.

Rendered follow-up: future-dated assigned programs are grouped separately with start dates and retain their future-editor action. Assigned programs remain published under the existing backend contract; source archival does not silently update member copies. The [scheduled-program check](scheduled-results.json) verifies default collapse, explicit opening, working editing access and unchanged historical actuals.
